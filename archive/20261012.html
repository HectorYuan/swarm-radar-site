本刊定位

面向多智能体编排（swarm / agentic workflow）的每日情报出版物。只收录「直接是编排的产品/论文/框架/重大发布」与「agent 生态重要动态」两档，其余丢弃不占版面。

覆盖范围

六源：OpenAI 官方博客、Anthropic、HuggingFace、GitHub（API 实查星数核验）、arXiv、Product Hunt。本期 3 源在线共产出 31 条原始条目，7 日滚动窗口。

发布节奏

每日一轮：采集 → 分级（high / medium）→ 富化（stars / license / abstract / README 首段）→ 建议提炼。URL 索引按 date_seen 本地口径七日去重，持续信号跨日累计。

读者画像

AgentSwarm 核心维护者与提案作者。每条建议都对照本仓 AGENTS.md / features.yaml 注册表落点，读完可直接转 AS-PROP 提案。

价值主张

不做新闻转发。每条条目回答三个问题：外部做法是什么、与本仓机制的差距在哪、下一步建议以什么优先级落到哪个文件。差距必须带行号锚点。

接入方式

数据面：classified.json（19 条精选）· enrich.json（31 条元数据+素材）· candidates.json（原始池+源状态）· url_index.jsonl（跨日索引）。管线产物即本刊数据源。

本期你的 1 件事

从 16 条建议中按 影响 × 逆成本 × 跨期权重 选出的 Top 1
TOP 1 · P1 · 来源 LegalOn × Codex（openai.com 2026-10-08）

在 modelswarm 路由里加 task_type → model tier 映射，与 per-task token 预算联动

LegalOn 用 Astra / Sol / Luna 按任务分工 + 预算档位管理，把日 Codex 成本降 65% 而开发速度不降；Asana 同型做法降本 76×、提速 5×。本仓 llm_model_routing_model_driven(:1012) 的 canonical _resolve_route 目前按 provider/key 健康解析路由，缺显式 task→model 分层——这是 16 条建议里唯一「影响面覆盖每一次 LLM 调用、而改动集中在一个函数」的条目，故列本周首位。

STEP 1 · 2d

在 swarm/llm/providers/modelswarm.py::_resolve_route 增加 task_type→tier 映射（cheap/fast vs heavy），任务类型由调用方显式声明，缺省回落现行为。

STEP 2 · 1d

与 O3 per-task token budget（:2798 五处透传）联动：tier 决定预算档位，超档熔断而非静默升级。

STEP 3 · 观察

配置变更纳入 key_pool_health(:2024) 30min 对账；先 warning 观察一周再考虑把「未声明 tier」升级为 gate。
